## 1. 多态如何做到“增加子类不改老代码”？体现了什么设计原则？

调用方使用父类或接口类型编程，调用约定的方法；运行时动态绑定到实际对象重写的实现。例如，遍历 `Record[]` 时始终调用 `summary()`，新增加的记录子类重写此方法后，原来的遍历代码不需要改变。这体现了**开闭原则**：对扩展开放，对已有代码的修改关闭。创建对象或注册插件仍需要配置，例如本实验通过服务配置注册分析器，并不意味着所有配置都无需变化。

## 2. 抽象类和接口分别适合什么场景？本实验各用在哪里？

接口适合定义不同实现都应遵循的能力或协议；Java 类可以实现多个接口。`Analyzer` 规定 `analyze(Dataset)`，主程序持有 `Analyzer[]`，不用依赖各个具体分析器。接口中的默认 `printResult` 为直接实现接口的类提供基本打印方式。

抽象类适合相关类共享状态和实现：`BaseAnalyzer` 实现 `Analyzer`，保存 `name` 并复用 `printResult`，同时将 `analyze` 留给子类实现。四个分析器继承该抽象类。Java 类只能直接继承一个类，因此需要组合多种能力时接口更灵活。

## 3. `Record r = new ScoreRecord(...)` 中，`r` 能调用 `ScoreRecord` 特有方法吗？为什么？如何调用？

不能直接调用 `r.getScore()`：编译器按引用的声明类型 `Record` 检查可调用成员，而 `Record` 没有声明 `getScore()`。不过 `r.summary()` 可以调用；因为子类重写了该方法，运行时执行 `ScoreRecord` 的版本。

确认真实类型后可安全地向下转型，例如 JDK 17 中：

```java
Record r = new ScoreRecord(1, 90);
if (r instanceof ScoreRecord scoreRecord) {
    System.out.println(scoreRecord.getScore());
}
```

也可以在 `instanceof` 检查后写 `((ScoreRecord) r).getScore()`；对不兼容的对象直接强制转换会导致 `ClassCastException`。
